# バージョン点検の手順

## 位置づけ

1. 道具のバージョンの正本は、`video-shorts/toolchain.json` と `video-shorts/requirements.txt` とする。
2. 使用時は、正本で指定された版だけを使う。doctor の照合で不一致が出た道具は使わない。
3. 更新は日常の使用中には行わない。更新は月1回の定期点検の時だけ、まとめて行う。
4. doctor は、最終点検日（`toolchain.json` の lastVersionCheck）から30日以上過ぎると、点検時期であることを「要対応」として表示する。
5. 点検の結果は、この文書の「点検記録」へ追記する。

## 新版の確認

1. 正本に載る道具の全件について、新しいバージョンが出ているかを確認する。
   - ffmpeg / ffprobe、Node.js、Python、deep-filter は、`toolchain.json` に書かれた取得元で確認する。
   - Python パッケージ（faster-whisper、groq、av、scenedetect、librosa）は、PyPI で確認する。
2. 新版が出ていない道具は、点検記録にその旨を書いて終える。
3. 新版が出ている道具だけを、更新の候補とする。

## 動作確認

1. 候補の道具を、新しい版へ入れ替える。候補の全件を入れてから確認する。
2. 既存テスト一式（`video-shorts/tests/` 配下の全ファイル）を実行し、全件合格を確認する。
3. 次のコマンドで doctor を実行し、バージョン照合以外の項目が全て OK であることを確認する。バージョン照合は、正本の指定を書き換える前なので、不一致で失敗するのが正常である。

```
node src/edit-job.mjs doctor
```

## 指定の書き換え（合格した場合）

1. テスト全件合格と doctor（バージョン照合以外）の全項目 OK の両方を満たした場合のみ、正本の指定を新しい版へ書き換える。
   - 実行ファイルの道具は `toolchain.json` を書き換える。
   - Python パッケージは `requirements.txt` を書き換える。
2. 書き換えた後に doctor を再実行し、バージョン照合を含む全項目が OK であることを確認する。
3. 点検記録に、日付と、書き換えた道具と版（旧→新）と、テスト結果を書く。
4. 最終点検日の書き換えと公開は、「点検の締め」に従う。

## 不合格の場合

1. 正本の指定は書き換えない。
2. 入れ替えた道具を、指定された版へ戻す。
3. 点検記録に、日付と、対象の道具と新版の版と、不合格の理由を書く。
4. 次回の点検で同じ新版を候補にするときは、前回の不合格の理由を先に確認する。
5. 最終点検日の書き換えと公開は、「点検の締め」に従う。

## 点検の締め

1. 結果にかかわらず（新版なし・合格・不合格のいずれでも）、`toolchain.json` の最終点検日（lastVersionCheck）を、点検当日の日付へ書き換える。
2. 点検記録への追記と最終点検日の書き換えを含めて、変更を公開する（GitHub へ push する）。
3. 公開の後に doctor を実行し、点検時期の表示（要対応）が出ていないことを確認する。

## 点検記録

1. 点検のたびに、次の形で追記する。

```
### YYYY-MM-DD
- 対象: <道具と版>
- 結果: 合格（指定を書き換えた）／不合格（指定は変更なし）／新版なし
- 理由・テスト結果: <内容>
```
